# Implement companionship as a first-class runtime mode

Companionship is not a Tenant Skill layered over the coding agent. A single deep Companion Runtime receives the participant, current messages, and event sink, then owns version resolution, layered context, thinking level, stream-versus-buffer policy, bounded read-only web search, review, and asynchronous memory/profile work. Its exact prompt replaces the coding prompt and contains only the locked baseline, versioned behavior, current time, and filtered companion context. Pi JSONL remains the raw transcript and active runtime record; tenant SQLite stores assignments, consent, confirmed memories, companion profile, summaries, reviews, and evaluation metadata. Delivery proceeds through three vertical stages: core shell/runtime/config/evals; memory/profile controls; then review, improvement, migration, and metrics.
