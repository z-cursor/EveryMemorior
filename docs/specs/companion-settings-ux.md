# 陪伴管理设置：信息架构与验收标准

## 问题与边界

团队页的成员入口被重复的配置、评测和试用功能挤到末尾，且页面没有自己的滚动容器。独立治理页只有通用外壳，没有内部排版。租户名称与 Tenant Membership 角色容易混淆；零样本指标被当作完整仪表盘展示。

本次只调整现有设置体系内的前端。保留 API、租户边界、身份、平台对话底线、不可变配置版本、人工确认和迁移审计；不创建真实账号、不修改角色、不运行真实模型评测、不部署。

## 任务与层级

### 团队与成员

首屏依次呈现：当前租户和当前身份、主操作「邀请陪伴成员」、Member 体验路径、成员列表。邀请表单默认 Member，并说明 Member 进入陪伴对话，Admin / Owner 进入管理工作台。生成链接后解释复制、无痕窗口接受、登录验证的下一步；复制失败保留可选中的链接。

待接受邀请位于成员列表之后。租户切换、新建租户及成员技能放在清楚标记的次级折叠区。明确「创建租户不会创建 Member 账号」。团队页不再请求或编辑陪伴治理数据，技能加载失败也不能挡住成员列表。

### 陪伴质量治理

页首显示发布状态与可操作的下一步。内容分为四个工作区：

1. 配置与发布：行为文档、运行参数说明、保存为新草稿、版本与评测记录。引导为「编写草稿 → 快速评测 → 人工确认发布」。不能发布时说明具体缺项。
2. 人工复核：仅呈现已授权的必要片段、具体复核决定、基于证据的改进建议。建议接受后只是新草稿，不自动发布。
3. 内部试用：选择陪伴成员、纳入脚本任务、进入自由聊天、明确记录继续意愿；有数据后显示分子/分母、缺失及响应分位数。零样本不是 0% 成功率。
4. 迁移与审计：选择参与者与已发布版本、先预览差异、单独确认写入；支持批量迁移与有记录的回滚。审计默认收起。

服务端发布条件是：同一配置版本至少一次已完成评测，致命问题为零且平均分不少于 85。前端只解释和预检，服务端仍为最终权威。500 题评测是扩大内部试用的门槛，不伪装成初次发布门槛。评分校准未完成时不鼓励用小幅分差做结论。

## 视觉与交互规则

沿用现有主题语义色，不另造品牌。页面标题 22px、分区标题 16px、正文 14px、说明 12–13px；正文行高 1.6。页面间距 24px，卡片内边距 20–24px，分组间距 16px。卡片边界用于划分任务，不把每个指标都变成同等权重的模块。

主操作使用实色按钮，普通操作为描边或文字按钮，危险操作保留明确文案和确认。表单必须有可见标签、帮助文字、焦点态及错误态。页面承担纵向滚动；窄屏改为单列，只有表格允许自身横向滚动。加载、失败、空数据和成功必须区分；异步操作给出真实工作状态，不伪造百分比。

## 验收

- 桌面首屏可见成员列表和邀请入口；无须寻找页面末尾的「用户与权限」。
- 邀请默认 Member，取消或失败不生成伪成功；链接可手动复制。
- 团队页不访问治理 API；治理页中空数据解释下一步。
- 编辑中的文档在刷新数据、切换工作区后保留；保存生成不可变新版本。
- 发布条件不满足时有可见原因；确认前不发布；迁移预览前后都不暗中改角色。
- 真实租户和模型数据不被视觉测试修改；使用内存 API fixtures 检查桌面、移动端、暗色、错误和操作路径。
